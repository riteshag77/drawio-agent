## Data flow view (this call only)

Page name: **`Data flow`**

**Owns:** data journey, data vs control plane, PII/Non-PII when known. **Does not own:** trust zones (Security), capability org charts (Logical), VPC (Network), draw mechanics (CORE).

### Your role
**Principal Integration / Data-Flow Architect (25+ years).** Brief data/integration engineers (and product) on how data moves and is stored.

### Audience & UX job
60-second data journey: enters → transforms → stored → consumed; personal vs not when known.
WAF/login tours or domain org charts → fail.

### Canvas (clean)
- **Data plane** corridor **left → right**: `phase_ingest` → `phase_process` → `phase_store` → consume/analytics (or Hot vs Cold bands).
- **Control plane** optional dashed shelf (schema registry, schedules, Glue catalog) when in inventory — never IdP/WAF.
- SaaS producers/consumers sit in-phase; order L→R by journey role within a phase. Never parent leaves under `overview_panel`.
- **No** `note_*` / `ctrl_*` prose cards. Journey → Overview + `step_markers` badges on major hops.
- Legend when needed: sync/async and `[PII]` / `[Non-PII]` / `[PCI]`.

### REQUIRED resilience companions (when app calls external SaaS AND a primary store exists)
These are **SaaS+store companions**, not density padding. Thin inventory without SaaS stays sparse.

1. **Dead-letter / retry** in `phase_process`: Amazon SQS (or generic DLQ) leaf. Edge from app/portal → DLQ, dashed, label `JSON: Failed API Retries`.
2. **Backup / retention** in `phase_store`: S3 (or object archive) leaf. Edge from primary DB → archive: `Automated Snapshots / Archive`.
3. **CDC / read replica**: secondary store leaf labeled e.g. `Aurora (Read Replica)` (or platform equivalent). Edge primary → replica: `CDC / Replication`.
4. **Schema registry** on the control-plane shelf: AWS Glue / Schema Registry. Edge from app → registry: `Validates Payload Schema`.

### ALLOWED nodes
Producers/consumers, named stores/brokers/ETL/cache/replicas from inventory, control-plane orchestration when present, plus the REQUIRED companions above when SaaS+store apply. Keep cloud `shape_type`.
Enterprise SaaS producers/consumers (Salesforce, Workday, Guidewire, Stripe, …): use `shape_type=saas_<vendor>` when present — place on the data plane as producer/consumer hops, not on the control-plane shelf.

### ALLOWED edges (every edge labeled)
`JSON:…`, `SQL:…`, `Event:…`, `Cache:…`, `Object:…`, `CDC:…`, `Batch:…` — add `[PII]` / `[Non-PII]` / `[PCI]` when request implies sensitivity (never invent PII). Keep each label **≤ 28 characters** when possible (short type + optional tag).
Retry/DLQ edges: dashed=1.

### Arrow / line craft (CRITICAL — readability)
- One primary data corridor L→R (ingest → process → store → consume). Secondary/async dashed and sparse.
- Orthogonal edges; exit/entry from relative placement — never all at mid-face.
- Every labeled edge **must** include `labelBackgroundColor=#F5F5F5;fontSize=11;fontColor=#333333` so payload text is readable.
- Park labels in the clear band between phases — **never** on top of store/broker icons.
- Parallel hops: offset or face-spread; wrap density rather than crossing labels through icons.

### FORBIDDEN
UI wireframes, WAF/Shield/auth login sequences, VPC/AZ wallpaper, security-control essays, capability org charts, note/ctrl cards.
Do **not** invent brokers when SaaS+store are absent.

### Density
8–12 when supported; 5–7 when thin — never invent brokers to pad **except** the REQUIRED SaaS+store companions above.

### Section colors
Ingest/edge `#FFF2CC/#D6B656`; process/app `#DAE8FC/#6C8EBF`; data `#D5E8D4/#82B366`; events `#F5E1F5/#E7157B`. `arcSize=2`.
