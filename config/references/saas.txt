━━━ Enterprise SaaS shape_types ━━━
Server resolves saas_* via curated stencil icons under static/saas-icons/ (embedded as data-URI image styles).
Leaf style is a grey placeholder + shape_type=saas_<vendor>; never derive a draw.io style or stencil string for these — the key alone is all the IR needs.
Expand this catalog by industry section as needed. Vendors are ordered L→R by journey role
(identity → experience → workforce → industry → payments → collab) — never one mega SaaS container.

Every key below has its own distinct, real, branded icon — copy the key that
actually matches the vendor. Never reuse a listed vendor's key for a
different, unrelated vendor just because it's a name you recognize (e.g. a
generic "market data vendor" or "clearinghouse" the brief never names is not
Salesforce or Stripe just because those are familiar keys) — that renders the
wrong company's logo, a worse mistake than an unresolved placeholder. If the
actual vendor genuinely is not one of these, invent a new `saas_<name>` key
instead — it safely renders as a generic labelled placeholder.

This applies leaf-by-leaf, not just once: "three external clearinghouses"
with no real names given is three *different* unresolved vendors, so it's
three *different* invented keys (`saas_clearinghouse_a`, `saas_clearinghouse_b`,
`saas_clearinghouse_c`, or similar per-instance names) — never three copies of
the same real vendor's key (all three as `saas_stripe`) and never three
different but equally wrong real vendors borrowed to fill the slots (`saas_fis`,
`saas_fiserv`, `saas_temenos`). None of those are the clearinghouses the brief
described; a generic placeholder per leaf is honest, a borrowed real brand
per leaf is not.
