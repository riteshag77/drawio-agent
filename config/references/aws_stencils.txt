# AWS services — `shape_type` vocabulary

Copy a key verbatim into a leaf's `shape_type`. These are already in the form
the IR expects; do not derive, prefix or reformat them. A service that is not
listed still takes your best semantic guess in the same `aws_<service>` shape —
an unresolved key renders as a labelled grey placeholder, which is strictly
better than a confidently wrong icon.

Never reuse another leaf's key for a different service just because it's
already in front of you — e.g. IAM, KMS and CloudWatch are three different
services and must not all resolve to the same key (such as `aws_directory_service`,
which is a fourth, unrelated service). Two different leaves sharing one icon
reads as a worse mistake than either one showing an unresolved placeholder.

Icon artwork is resolved server-side from this key — never emit a draw.io style
or stencil path.

## Keys with no usable icon — never emit these
Use the suggested replacement instead; these resolve to a blank or wrong glyph.

| Do not use | Use instead |
|---|---|
| aws_dynamodb_table, aws_dynamodb_stream | aws_dynamodb |
| aws_s3_bucket | aws_s3, labelled with the bucket name |
| aws_kinesis_data_streams | aws_kinesis |
| aws_msk | aws_managed_streaming_for_kafka |
| aws_iam_identity_center | aws_single_sign_on |
| aws_vpc_peering, aws_peering_connection | aws_peering |
| aws_endpoint | aws_endpoints |
| aws_general_saml_token | aws_iam |
